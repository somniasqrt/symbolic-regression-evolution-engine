# symreg — пошук формул за даними

`symreg` — рушій **символьної регресії** на Rust. На вхід він отримує таблицю чисел (наприклад, виміри з експерименту), а на виході дає набір **формул**, які ці числа пояснюють. Форму формули заздалегідь не задають: не треба казати «шукай поліном» чи «шукай синусоїду». Рушій сам підбирає і структуру виразу, і константи в ньому.

Підхід базується на статті *Schmidt & Lipson, "Distilling Free-Form Natural Laws from Experimental Data", Science 324 (2009)*: популяція випадкових формул еволюціонує методом **генетичного програмування** (GP), а результатом є не одна «найкраща» формула, а **Парето-фронт** — компроміси між точністю і простотою.

## 1. Як це працює в двох словах

```
дані (X, y)
   │
   ▼
[1] створюємо сотні випадкових формул
   │
   ▼
┌─► [2] рахуємо, наскільки кожна формула помиляється на даних
│   [3] якщо вже досить точно або закінчився час — стоп
│   [4] найкращих переносимо в наступне покоління як є
│   [5] обираємо «батьків» турніром
│   [6] схрещуємо батьків: обмінюємо шматки формул
│   [7] мутуємо: дрібно змінюємо або вирощуємо нову гілку
└── нове покоління
   │
   ▼
[8] Парето-фронт: від найпростішої до найточнішої формули
```

Кожна формула — це **дерево виразу** (AST). Наприклад, `2^x + x`:

```
        +
       / \
      ^   x
     / \
    2   x
```

Еволюція працює саме з деревами: схрещування обмінює піддерева між двома формулами, мутація замінює вузол або цілу гілку.

## 4. Модель даних

### 4.1 `Node` — вузол дерева виразу

```rust
pub enum Node {
    Var(usize),                         // змінна: індекс стовпця в рядку даних (v0, v1, ...)
    Const(f64),                         // числова константа
    Unary(UnaryOp, Box<Node>),          // f(a)
    Binary(BinaryOp, Box<Node>, Box<Node>), // a ∘ b
}
```

Основні методи:

| Метод | Що робить |
|---|---|
| `evaluate(&[f64]) -> f64` | Рахує значення формули для одного рядка даних |
| `count()` | Кількість вузлів — це **складність** формули |
| `depth()` | Глибина дерева; **листок має глибину 1** |
| `get_subtree(i)` / `get_subtree_mut(i)` | Піддерево з префіксним (DFS) індексом `i`; панікує, якщо індексу немає |
| `replace_subtree(i, node)` | Замінює піддерево з індексом `i`; панікує, якщо індексу немає |

**Індексація вузлів** — префіксний обхід (спочатку вузол, потім лівий нащадок, потім правий). Для `2^x + x`: `0` — `+`, `1` — `^`, `2` — `2`, `3` — `x`, `4` — `x`. Індекс від `0` до `count() - 1` завжди валідний, тож для вибору випадкового вузла досить `rng.random_range(0..tree.count())`.

**Друк**: `((2.0000 ^ v0) + v0)`, `sin(v0)`, `|v0|`, `-(v0)`.

### 4.2 Оператори

Усі оператори **захищені**: на будь-якому скінченному вході вони повертають скінченне число. Інакше одна погана гілка дала б `NaN`, і вся формула стала б непридатною, навіть якщо решта дерева корисна.

**Бінарні (`BinaryOp`)**

| Оператор | Звичайний випадок | Захист |
|---|---|---|
| `Add`, `Sub`, `Mul` | `a + b`, `a − b`, `a · b` | — |
| `Div` | `a / b` | якщо `|b| ≤ 1e-6`, ділимо на `±1e-6` зі знаком `b` |
| `Pow` | `a ^ b` | якщо `a < 0` і `b` дробовий — рахуємо `|a| ^ b`; результат обрізається до `±1e12` |

**Унарні (`UnaryOp`)**

| Оператор | Звичайний випадок | Захист |
|---|---|---|
| `Neg`, `Abs` | `−a`, `|a|` | — |
| `Sin`, `Cos` | `sin a`, `cos a` | — |
| `Tan` | `tan a` | обрізається до `±1e12` |
| `Cot` | `1 / tan a` | якщо `|tan a| ≤ 1e-6`, ділимо на `±1e-6` |
| `Exp` | `e^a` | аргумент обрізається до `[−50, 50]` |
| `Ln` | `ln |a|` | якщо `|a| ≤ 1e-9`, повертає `0` |

### 4.3 `OperatorSet` і `TreeGenerator`

`OperatorSet` — які оператори дозволені в пошуку. Менший набір звужує простір пошуку і пришвидшує збіжність: якщо фізично очевидно, що тригонометрії немає, її краще вимкнути.

`TreeGenerator` збирає все, що потрібно для генерації дерев:

| Поле | Значення |
|---|---|
| `rng` | генератор випадкових чисел |
| `ops` | дозволені оператори |
| `const_range` | діапазон випадкових констант, напр. `-10.0..10.0` |
| `max_depth` | максимальна глибина дерева (рахується з 1) |
| `vars_len` | кількість змінних у даних |

### 4.4 `Dataset`

```
names:   ["x", "y"]
inputs:  [[1.0, 2.0],     outputs: [5.0,
          [2.0, 3.0],               13.0,
          [3.0, 4.0]]               25.0]
```

Кожен рядок `inputs` — один вимір, `outputs[i]` — очікуване значення для нього. `Var(k)` у формулі бере `inputs[i][k]`.

`Dataset::new` перевіряє: колекції не порожні, `inputs.len() == outputs.len()`, кожен рядок має стільки ж значень, скільки є `names`, і немає `NaN`/`inf`.

### 4.5 `Individual`

Одна особина популяції: дерево + його оцінка.

| Поле | Значення |
|---|---|
| `node` | дерево формули |
| `fitness` | MSE на датасеті; `INFINITY` до першої оцінки або якщо формула дала `NaN`/`inf` |
| `complexity` | `node.count()`, оновлюється при кожній оцінці |

## 5. Алгоритм поетапно

### Етап 1. Початкова популяція (Ramped Half-and-Half)

**Навіщо.** Якщо всі стартові формули схожі, еволюції нема з чого обирати. Потрібна суміш простих і складних, «кущистих» і «худих» дерев.

**Як.**
1. Глибини від `2` до `max_depth` ділять популяцію порівну. При `N = 500` і `max_depth = 6` маємо 5 рівнів по 100 дерев.
2. На кожному рівні половина дерев будується методом **Full**, половина — **Grow**.
3. **Full**: поки не досягнуто глибини, кожен вузол — оператор. Усі листки лежать рівно на заданій глибині, дерево «повне».
4. **Grow**: корінь завжди оператор, далі кожен вузол з імовірністю 70% оператор, 30% листок. Дерева виходять різної форми і розміру.
5. Оператор: 70% бінарний, 30% унарний. Листок: 50% змінна, 50% константа з `const_range`.

**Виклик:** `Node::generate_random_tree(&mut generator, method, 1)` — **стартова глибина 1**, бо корінь сам по собі вже має глибину 1.

**Обмеження.** Дублікати не відсіюються. Глибина 1 не використовується — це лише одна змінна або константа.

### Етап 2. Оцінка пристосованості (fitness)

**Навіщо.** Щоб порівнювати формули між собою, кожній потрібне одне число «наскільки погано».

**Як.**
1. Для кожного рядка даних `i`: `pred_i = tree.evaluate(inputs[i])`.
2. `MSE = (1/n) · Σ (pred_i − outputs[i])²`.
3. Якщо MSE не скінченне (`NaN` або `inf`), `fitness = INFINITY`. Така формула програє **будь-якій** формулі зі скінченною похибкою.
4. `complexity = count()`.
5. Особини оцінюються незалежно одна від одної, тому це паралелиться через `rayon::par_iter_mut()` без жодної синхронізації.

**Обмеження.** MSE чутливий до масштабу `y`: на даних зі значеннями близько `1e6` похибки будуть величезні. Для таких даних варто нормалізувати `y` або перейти на `1 − R²`. MSE також чутливий до викидів, а в статті з цієї причини використовують середню лог-похибку (див. [розділ 7](#7-відмінності-від-статті)).

### Етап 3. Умова зупинки

**Навіщо.** Не крутити еволюцію довше, ніж треба.

**Як.** Зупиняємося, якщо виконано хоча б одне:
- найкращий `fitness ≤ target_mse` (напр. `1e-6`);
- досягнуто `max_generations` (напр. `500`).

Після зупинки переходимо до етапу 8.

**Що можна додати.** Зупинку через стагнацію: найкращий результат не покращувався `K` поколінь. Або ліміт за часом.

### Етап 4. Елітизм

**Навіщо.** Без нього найкращу формулу можна випадково втратити: її зіпсує мутація або вона не виграє жодного турніру.

**Як.** Популяцію сортуємо за `(fitness, complexity)`, і топ-`E` особин (`E` = 1–2) копіюються в наступне покоління без змін.

**Обмеження.** Занадто велике `E` зменшує різноманіття, і популяція швидко збігається до однієї формули.

### Етап 5. Турнірна селекція

**Навіщо.** Обрати батьків так, щоб кращі мали більше шансів, але слабші теж іноді проходили. Так зберігається різноманіття.

**Як.**
1. Випадково беремо `K` особин (`K = 4`).
2. Перемагає та, в якої менший `fitness`.
3. Якщо фітнеси відрізняються менше ніж на `ε` (відносно), перемагає та, що має менший `complexity`. Це **парсимонія**, тобто принцип бритви Оккама.

**Чому `ε`, а не точна рівність.** Два `f64` майже ніколи не рівні точно, і без допуску правило парсимонії фактично не спрацює.

**Обмеження.** Більше `K` — сильніший тиск відбору і швидша, але ризикованіша збіжність. Менше `K` — повільніше, але різноманітніше.

### Етап 6. Кросовер піддерев

**Навіщо.** Комбінувати вдалі шматки двох різних формул. Наприклад, одна формула знайшла доданок `x²`, інша — `sin(y)`, а їхній нащадок може отримати обидва.

**Як.** З імовірністю `p_cross` (≈ 0.7–0.8):
1. У кожному батьку обираємо випадковий вузол: `i = random(0..count())`.
2. `a = parent_a.get_subtree(i).clone()`, `b = parent_b.get_subtree(j).clone()`.
3. `child_a.replace_subtree(i, b)`, `child_b.replace_subtree(j, a)`.
4. Якщо `child.depth() > max_depth`, такий нащадок відкидається, і замість нього береться копія батька.

Інакше (з імовірністю `1 − p_cross`) нащадки — копії батьків.

**Обмеження.** Листків приблизно стільки ж, скільки внутрішніх вузлів, тому рівномірний вибір часто обмінює лише листки, а це дрібна зміна. Класичне рішення (Koza): обирати внутрішній вузол з імовірністю 90%.

### Етап 7. Мутація

**Навіщо.** Кросовер тільки перемішує те, що вже є в популяції. Мутація вносить новий матеріал.

**Як.** З імовірністю `p_mut` (≈ 0.1–0.2) застосовується одна з двох:

1. **Точкова мутація** — форма дерева зберігається:
   - `Binary(op, ..)` — замінюємо `op` на інший бінарний (`+` → `−`);
   - `Unary(op, ..)` — на інший унарний (`sin` → `cos`);
   - `Const(c)` — додаємо шум: `c + N(0, σ)`;
   - `Var(k)` — замінюємо на іншу змінну.
2. **Мутація піддерева** — випадковий вузол замінюється новим деревом із `Grow` невеликої глибини (2–3). Перевірка `max_depth` така сама, як у кросовері.

**Обмеження.** Точкова мутація не змінює складність, мутація піддерева може її збільшити. Без парсимонії дерева з поколіннями розростаються (**bloat**).

### Етап 8. Парето-фронт

**Навіщо.** Немає однієї «правильної» відповіді: `y ≈ 2x` з MSE `0.1` може бути кориснішою за 40-вузлового монстра з MSE `0.001`. Користувач має бачити весь вибір.

**Як.**
1. Протягом усієї еволюції в архів зберігаються найкращі формули для кожної складності: `complexity → найменший fitness`.
2. Формула **домінована**, якщо існує інша, яка не гірша за обома критеріями і краща хоча б за одним.
3. Усі доміновані відкидаються. Те, що лишилося, сортується за складністю.

Результат виглядає приблизно так:

```
complexity   MSE        формула
1            12.4       v0
3            0.83       (v0 * v0)
5            0.0021     ((v0 * v0) + 1.0013)
9            0.0000     ((v0 * v0) + cos(v1))
```

**Як обирати.** У статті помічено, що на фронті зазвичай є «злам»: при певній складності точність різко покращується, а далі майже не росте. Формула на зламі — найімовірніший кандидат на справжній закон.

## 7. Відмінності від статті

| | Стаття (Schmidt & Lipson) | `symreg` |
|---|---|---|
| **Що шукаємо** | неявний закон `f(x, y, …) = const` (енергія, інваріант) | явну залежність `y = f(x₀, …, xₖ)` |
| **Фітнес** | збіг часткових похідних формули з похідними з даних, середня лог-похибка | MSE між прогнозом і `y` |
| **Представлення** | ациклічний граф (список операцій до 128 штук, з перевикористанням піддерев) | дерево (`enum Node`) |
| **Кросовер** | одноточковий по списку операцій | обмін піддеревами |
| **Константи** | окремо підлаштовуються (parameter tuning) | лише мутація шумом (поки що) |
| **Масштабування** | острівна модель + fitness prediction на 32 ядрах | одна популяція, rayon |

**Чому так.** Явна регресія простіша і покриває більшість практичних задач, де є «вхід → вихід». Критерій часткових похідних потрібен, щоб знаходити закони збереження в системах без явного виходу. Його можна додати як окремий тип фітнесу, не чіпаючи решту рушія.

**Що варто взяти зі статті в першу чергу:**
- **Оптимізація констант.** У статті видно (Fig. S1), що в фіналі пошук знаходить правильну **структуру**, а точні коефіцієнти доводяться локальною оптимізацією. Мутація шумом робить це повільно. Кілька кроків градієнтного спуску або Левенберга–Марквардта по `Const`-вузлах для топ-особин суттєво пришвидшать збіжність.
- **Лог-похибка** `−(1/N) Σ log(1 + |err|)` як альтернатива MSE: вона стійкіша до викидів і великих значень.

## 8. Обмеження та відомі компроміси

- **Захищені оператори змінюють математику.** `ln(−4)` дає `ln 4`, `(−8)^(1/3)` дає `2`, `1/0` дає `1e6`. Знайдену формулу треба перевіряти на тій області, де вона буде використовуватись.
- **Розриви.** `ln` біля нуля стрибає в `0`, `Div` — в `±1e6·a`. Еволюція іноді використовує такі артефакти, щоб «підігнатися» під окремі точки.
- **Немає спрощення формул.** `(x − x) + 0 * y` залишиться як є. Спрощувач (константна згортка, `x − x → 0`) зробив би результат читабельнішим, а складність — чеснішою.
- **Немає валідаційної вибірки.** Фітнес рахується на всіх даних, тож формула може перенавчитися. Варто відкладати частину рядків для перевірки Парето-фронту.
- **Рекурсія по дереву.** `evaluate`, `count`, `depth`, `get_subtree` рекурсивні; при `max_depth ≤ 10` це не проблема для стеку.
- **`Vec<Vec<f64>>`** для даних неоптимальний для кешу; на великих датасетах варто перейти на плаский буфер.
